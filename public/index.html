    A LITTLE CONTEXT

    The IPC field guide

    Use these basics to connect the runnable demos to your own Node.js processes.

    01 / MESSAGE FLOW

    Connect, emit, respond

    The server starts listening. The client waits for connect, emits a named event with data, and listens for the server's response event.

    clientapp.message →← app.replyserver
    02 / DESIGN A PROTOCOL

    Name events and shape payloads

    Use stable, namespaced event names such as math.add and document each payload. Include a request ID when responses need to be correlated, and validate data before acting on it.

    03 / CHOOSE A TRANSPORT

    Same machine or network?

    Choose a local socket when both processes live on one host. Choose TCP for reliable, ordered communication over IP. Use UDP only when your application can tolerate missing or reordered datagrams.

    04 / HANDLE LIFECYCLE

    Plan for disconnects and timeouts

    Connections can close and requests can take too long. Listen for disconnects, set a timeout for expected replies, and decide whether the caller should retry, fail, or reconnect.

    05 / MORE THAN ONE CLIENT

    Choose emit or broadcast

    Send to one client when its socket is known; broadcast only when every connected client should receive the event. Consider whether new clients need an initial snapshot.

    06 / PACKAGE SETUP

    Use the maintained package

    Install the scoped package and import its default IPC instance. Older tutorials may refer to a different package name.

    npm install @node-ipc/node-ipc
